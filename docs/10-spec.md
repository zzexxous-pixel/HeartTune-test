## 4. 컨셉 결정 사항

## 4-1. 측정 방식 — ✅ 확정: 손가락 PPG
| 방식 | 결정 |
|---|---|
| **A. 손가락 PPG** | ✅ **채택**. 검지를 후면 카메라+플래시에 대고 혈류 색 변화 측정 |
| B. 얼굴 rPPG | ⏸ **보류**. "재밌겠다"는 의견 → 향후 별도 기능으로 검토 |

**구현 파이프라인 (안)**
1. `getUserMedia({ video: { facingMode: 'environment' } })` + `torch: true` (플래시, 지원 기기만)
2. `requestVideoFrameCallback`으로 프레임 수신 → `<canvas>`에 축소 렌더링 (예: 64×64)
3. 프레임당 **평균 녹색채널(G) 값** 추출 → 시계열 배열
   *(PPG는 녹색광 흡수 변화가 가장 큼. 적색채널 대비 SNR 우수)*
4. 대역통과 필터 **0.7~4.0 Hz** (= 42~240 BPM) → 저주파 호흡·고주파 노이즈 제거
5. 주파수 분석: **FFT** (슬라이딩 윈도) + **자기상관(autocorrelation)** 병행 → 피크 BPM
6. 피크 검출로 **박동 간격(IBI)** 추출 → 변동성(RMSSD / CV) 계산

## 4-1b. 측정 진행 로직 — ✅ 확정

```
0초 ──────── 15초 ── 20초 ── 25초 ── 30초(기본 종료) ── 60초
 │            │       │       │        │
 준비/안정화   ①첫 BPM  ②갱신   ③갱신    ④최종 BPM + 부정맥 판정
 (신호 품질    표시
  체크)
```

| 시점 | 동작 |
|---|---|
| 0 ~ 15초 | 신호 수집 + **품질 체크** (손가락 압박·주변광). 안정화 전에는 BPM을 표시하지 않음 |
| **15초** | **첫 BPM 표시** — 이후 지루하지 않도록 실시간 피드백 시작 |
| 20초 / 25초 / … | **5초마다 BPM 갱신** (슬라이딩 윈도 재계산) |
| **측정 종료** (기본 30초) | **최종 BPM 확정 + 부정맥(리듬) 판정** 수행 |

- **왜 15초부터인가**: 0~15초 구간은 손가락을 대는 초기 안정화 구간이라 값이 튀기 쉬움. 15초부터 표시하면 신뢰도 있는 첫 값을 보여줄 수 있음
- **실시간 BPM 계산**: 15초 시점부터는 **슬라이딩 윈도 FFT**로 재계산. 윈도가 길어질수록 주파수 해상도가 좋아져 값이 점점 안정됨
  - 15초 윈도 @30fps = 450샘플 → 해상도 약 0.067Hz(≈4BPM) — 표시용으로는 충분
- **부정맥 판정은 마지막에만**: 전체 구간의 IBI 변동성을 계산하므로 중간 표시값과 무관하게 한 번만 판정
- **진행 피드백**: 남은 시간 링(원형 프로그레스) + 심장 박동 애니메이션으로 "지루함" 상쇄

> ⚠️ **초기 값 변동 안내 필요**: 15초 시점 값은 이후 갱신되며 바뀔 수 있음 → 화면에 **"측정 중… 최종값은 측정 완료 후 표시됩니다"** 문구 병기 권장

## 4-2. 판정 기준 (안) — 문구 확정 필요
| 판정 | 심박수(BPM) | 화면 문구(안) |
|---|---|---|
| 서맥 | < 60 | "심장이 느리게 뛰고 있어요" |
| **정상** | 60 ~ 100 | "정상 범위예요" |
| **빈맥** | > 100 | "심장이 빠르게 뛰고 있어요" |
| **리듬 불규칙** | BPM 무관, IBI 변동성 임계 초과 | "리듬이 고르지 않아요. 의사와 상담해 보세요" |

> ⚠️ 카메라 PPG로 **부정맥 판정은 근본적으로 한계**가 있음. "부정맥입니다"가 아니라 **"리듬이 고르지 않아요"** 수준의 안내로 표현해야 의학적·법적으로 안전.

> ⚠️ **측정 길이별 판정 범위**
> | 측정 시간 | 심박수(BPM) | 리듬(부정맥) 판정 |
> |---|---|---|
> | 15초 | ✅ 가능 (박동 15~25개) | ⚠️ 참고 수준 — 신뢰도 낮음 |
> | **30초 (기본)** | ✅ | ✅ **가능 (박동 30~50개)** |
> | 60초 | ✅ | ✅ 가장 안정적 |
>
> → **기본값을 30초로 정한 이유**: 리듬 판정에 필요한 최소 박동 수를 확보하면서도 사용자가 견딜 수 있는 길이. 15초 옵션은 "빠른 확인"용으로 두되, 리듬 판정 시 **"짧은 측정이라 참고만 하세요"** 안내 병기

## 4-5. 중장년 타깃 → UI 설계 원칙
- **기본 글자 18px 이상**, 핵심 수치는 **64px 이상**
- **탭 영역 최소 48×48dp** (손떨림·노안 고려)
- 화면 요소 최소화: 한 화면에 **"측정 시작" 버튼 하나**가 주인공
- 색상만으로 상태 전달 금지 → **색 + 아이콘 + 텍스트** 동시 사용 (색각 이상 대비)
- 측정 실패 시 원인을 **구체적으로** 안내 ("손가락을 조금 더 꾹 눌러주세요", "너무 밝은 곳이에요")
- 가족 공유: 결과를 **큰 글씨 이미지**로 저장해 카카오톡 등으로 전송 가능하게

## 4-6. 법적 표기 (필수)
- "본 앱은 의료기기가 아니며, 측정 결과는 참고용 정보입니다. 의학적 진단을 대체할 수 없습니다."
- 카메라 권한 요청 사유 고지
- 영상 데이터 서버 전송 없음(브라우저 내 처리) 명시 → 개인정보 신뢰도 확보

## 4-7. 측정 이력 — ✅ 브라우저 저장
- 저장소: **`localStorage`** (서버 없음 → 개인정보 리스크 0, 오프라인 동작)
- 저장 항목(안): `{ 측정시각, BPM, 판정결과, 리듬변동성, 측정길이, 신호품질 }`
- 표시: 최근 N건을 **그래프(추세선) + 목록**으로. 중장년 타깃이므로 "지난주보다 느려졌어요" 같은 **비교 문구**가 숫자보다 효과적
- ⚠️ **한계 고지 필요**: localStorage는 **브라우저·기기별** 저장이라 PC에서 측정한 값이 휴대폰에 안 보임. "이 기기에만 저장됩니다" 문구 명시
- ⚠️ localStorage 용량 한도(약 5MB) → 보관 개수 상한을 정하고 오래된 것부터 자동 삭제 (예: 최근 200건)

## 4-8. 결과 공유 — ✅ 이미지 저장
- **Web Share API** 우선 (`navigator.share({ files })`) → 모바일에서 카카오톡 등으로 바로 공유
- 미지원 브라우저(PC 등) 폴백: `<canvas>` → `toBlob()` → **다운로드 링크**
- 이미지 구성(안): 로고(오늘심박/HeartTune) + 큰 BPM 숫자 + 판정 문구 + 측정 시각 + 법적 고지 한 줄
- ⚠️ **가족 공유가 핵심 유스케이스**: 부모님이 혼자 보셔도 자녀가 바로 알아볼 수 있게 **큰 글씨·높은 대비**로 생성

## 4-9. PWA — ✅ 지원
- `manifest.webmanifest` + Service Worker 등록
- 아이콘: 192px / 512px / maskable, iOS용 `apple-touch-icon` 별도
- **오프라인 동작**: 정적 자원 캐싱 → 인터넷 없이도 측정 가능 (카메라는 로컬 API)
- 설치 유도: Android `beforeinstallprompt`, iOS는 **"홈 화면에 추가" 안내 배너** 필요 (자동 설치 프롬프트 미지원)
- ⚠️ iOS PWA는 localStorage가 **장기간 미사용 시 정리될 수 있음** → 이력 유실 가능성 고지

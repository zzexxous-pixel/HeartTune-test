## 4. 컨셉 결정 사항

## 4-1. 측정 방식 — ✅ 확정: 손가락 PPG
| 방식 | 결정 |
|---|---|
| **A. 손가락 PPG** | ✅ **채택**. 검지를 후면 카메라+플래시에 대고 혈류 색 변화 측정 |
| B. 얼굴 rPPG | ⏸ **보류**. "재밌겠다"는 의견 → 향후 별도 기능으로 검토 |

**구현 파이프라인**
1. `getUserMedia({ video: { facingMode: 'environment' } })` + `torch: true` (플래시, 지원 기기만)
2. `requestVideoFrameCallback`으로 프레임 수신 → `<canvas>`에 축소 렌더링 (예: 64×64)
3. 중앙 ROI의 채널 평균 추출: 적색 우세 조건이면 R, 그 외 G를 선택 → 시계열 배열
4. 대역통과 필터 **0.7~4.0 Hz** (= 42~240 BPM) → 저주파 호흡·고주파 노이즈 제거
5. 주파수 분석: **FFT** (슬라이딩 윈도) + **자기상관(autocorrelation)** 병행 → 피크 BPM
6. 피크 검출로 **박동 간격(IBI)** 추출 → 변동성(RMSSD / CV) 계산

## 4-1b. 측정 진행 로직 — 현행 구현

- 카메라 측정의 첫 3초 샘플은 안정화를 위해 버린다. 유효 샘플 약 5초를 확보한 뒤 경과 약 **8초부터 분석을 시도**한다. 이후 약 2초 간격으로 갱신한다. 품질≥50·추정 합의≥2이며 prior/hold에 의존하지 않는 경우에만 새 잠정 BPM을 표시한다. 경고 중에는 갱신하지 않고, 부적합하면 `--` 또는 직전 통과값을 유지한다. 첫 숫자를 8초에 반드시 표시한다고 보장하지 않는다.
- 측정 중에는 약 2초 간격으로 적응형 추적과 BPM 표시를 갱신한다.
- 설정한 15/30/60초 측정 종료 시 최종 결과와 전체 구간의 리듬 참고 신호를 표시한다.
- 링 진행률과 파형은 측정 중 계속 표시한다. 파형은 측정 전 빈 신호 영역의 옅은 격자를 표시하고, 측정 후 마지막 측정 파형을 유지한다.
- 15초 측정에는 짧은 측정 결과임을 알리는 참고 문구를 표시한다.


## 4-2. 결과 참고 신호 — UI 문구 확정
| 참고 항목 | 표시 기준(현행 DSP 기준 유지) | 화면 표시 |
|---|---|---|
| 서맥 | 심박수 < 60 BPM | "서맥 참고 신호" |
| 일반 범위 | 심박수 60~100 BPM | "정상 범위예요" |
| 빈맥 | 심박수 > 100 BPM | "빈맥 참고 신호" |
| 부정맥 참고 신호 | BPM과 무관하게 현행 IBI 변동 기준 초과 | "부정맥 참고 신호" |

세 항목(부정맥·서맥·빈맥)은 상세 시트에서 **각각 독립적으로** 표시한다. 기존 DSP는 irregular를 대표 `status`로 우선 반환하지만, 화면 플래그는 같은 60/100 BPM 경계를 재사용해 다른 조건도 함께 표시한다. **임계값과 신호처리 알고리즘은 이 UI 작업에서 바꾸지 않는다.** 상세 표시등은 빨강(신호 있음)/초록(신호 없음)이며, 상태 문구를 함께 제공한다. 측정 신호 품질은 별도 파랑/황색/회색 상태 체계로 구분한다.

> ⚠️ 카메라 PPG 결과는 진단이 아니다. 부정맥 여부를 단정하거나 건강을 보증하지 않고, 결과와 법적 고지에 참고용임을 명시한다.

> ⚠️ **측정 길이별 판정 범위**
> | 측정 시간 | 심박수(BPM) | 리듬(부정맥) 판정 |
> |---|---|---|
> | 15초 | ✅ 가능 (박동 15~25개) | ⚠️ 참고 수준 — 신뢰도 낮음 |
> | **30초 (기본)** | ✅ | ✅ **가능 (박동 30~50개)** |
> | 60초 | ✅ | ✅ 가장 안정적 |
>
> → **기본값을 30초로 정한 이유**: 리듬 판정에 필요한 최소 박동 수를 확보하면서도 사용자가 견딜 수 있는 길이. 15초 옵션은 "빠른 확인"용으로 두되, 리듬 판정 시 **"짧은 측정이라 참고만 하세요"** 안내 병기

## 4-6. 법적 표기 (필수)
- "본 앱은 의료기기가 아니며, 측정 결과는 참고용 정보입니다. 의학적 판단이나 진료를 대체할 수 없습니다."
- 카메라 권한 요청 사유 고지
- 영상 데이터 서버 전송 없음(브라우저 내 처리) 명시 → 개인정보 신뢰도 확보

## 4-7. 측정 이력 — ✅ 브라우저 저장
- 저장소: **`localStorage`** (브라우저 로컬 저장, 서버 전송 없음, 오프라인 동작; 기기 접근·브라우저 삭제·유실 위험은 남음)
- 저장 항목: `{ id, timestamp, bpm, status, irregular, cv, rmssdMs, duration, quality, beatCount, isShortMeasurement, waveform }`. `waveform`은 최근 최대 90개의 원시 샘플 값을 소수 4자리로 저장하며 전체 측정 원시 데이터가 아니다.
- 표시: 최근 최대 100건을 **그래프(추세선) + 목록**으로 표시한다.
- ⚠️ **한계 고지 필요**: localStorage는 **브라우저·기기별** 저장이라 다른 브라우저·기기와 이력이 공유되지 않음. "이 기기에만 저장됩니다" 문구 명시
- ⚠️ localStorage 용량 한도(약 5MB) → 보관 개수 상한을 정하고 오래된 것부터 자동 삭제. **확정: 최근 100건** (2026-10-21)

## 4-8. 결과 공유 — ✅ 이미지 공유·저장 (공유 아이콘)
- **Web Share API** 우선 (`navigator.share({ files })`) → 모바일에서 카카오톡 등으로 바로 공유
- 미지원 브라우저(PC 등) 폴백: `<canvas>` → 동기 `toDataURL()` → Blob/File → **다운로드** (모바일 사용자 활성화 유지를 위한 동기 인코딩)
- 이미지 구성 (2026-10-21 확정): 제목(ko: `오늘심박`, en: `HeartTune`; Web Share 메타데이터 제목과 별개) + 자세히 보기와 같은 내용(측정일시·측정시간·맥박·카메라 측정 파형·부정맥/서맥/빈맥/신호 품질 카드·참고 고지). 날짜는 이력과 같은 형식. 공유 진입점: 메인 결과 하단, 자세히 보기 헤더, 이력 자세히 보기 헤더
- ⚠️ **가족 공유가 핵심 유스케이스**: 부모님이 혼자 보셔도 자녀가 바로 알아볼 수 있게 **큰 글씨·높은 대비**로 생성

## 4-9. PWA — ✅ 지원
- `manifest.webmanifest` + Service Worker 등록
- 아이콘: 모든 용도 공통 192px / 512px(둥근 모서리+바깥 투명, r=70/512), iOS용 `apple-touch-icon`(동일 라운드 디자인) 별도
- **오프라인 동작**: 정적 자원 캐싱 → 인터넷 없이도 측정 가능 (카메라는 로컬 API)
- 설치 유도: Android `beforeinstallprompt`, 설정 시트의 설치 버튼만 사용한다. `beforeinstallprompt` 이벤트가 제공된 경우 노출하며, iOS 수동 안내 배너는 구현하지 않는다
- ⚠️ iOS PWA는 localStorage가 **장기간 미사용 시 정리될 수 있음** → 이력 유실 가능성 고지

## 4-10. 현행 코드와 원칙의 미결 차이

- 대기 파형은 캔버스 격자만 그리며 별도 신호 기준선은 없다. 기준선 추가 여부는 결정 대기.
- 진입 미리보기·측정 시작·카메라 변경 오류 및 측정 중 신호 경고는 메시지 영역이다. 권한 거부는 권한 안내, 그 외 열기 실패는 연결·다른 앱 사용 여부 확인 안내이며 디버그 콘솔을 언급하지 않는다. CSV 무샘플 토스트와 삭제 취소 알림은 유지한다.
- 18px 본문·48px 버튼은 목표 원칙이다. 현재 작은 화면·시트 헤더 등에 더 작은 값이 있어 충족 완료로 간주하지 않는다. 사용자 결정으로 현재 UI 크기는 유지한다(2026-10-27).
- 공유 PNG의 브랜드 마크는 헤더의 그라데이션·모서리·하트 크기와 위치로 통일한다. PNG 제목은 기존 오늘심박/HeartTune을 유지한다.
- 개발·프리뷰 환경 식별 규칙: `40-deployment-guide.md` 10절.

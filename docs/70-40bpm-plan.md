# 70 · 40 BPM 지원 확대: 구현 및 검증 기록

> 2026-10-27 사용자 승인으로 27번 구현. **코드 지원 범위 확대와 합성 회귀는 완료했으나, 실제 40 BPM 정확도·임상 리듬 검증 완료를 뜻하지 않는다.**
> 비교 기준: `c86b324`의 `src/dsp.js`. 제공된 실측 CSV 2개는 `tests/fixtures/ppg/`에 원본·SHA·용도 제한과 함께 보관했다.

## 1. 적용 범위와 유지 조건

| 항목 | 구현 / 결정 |
|---|---|
| Tracking | 40~195 BPM. 하한에서 보간값을 정수 BPM으로 반올림해 비교해 39.9 같은 수치 때문에 40 경계가 탈락하지 않게 함. 상한 195의 비교 방식 유지 |
| 새로 연 40~45 구간 | 45 미만 후보는 광대역 추정 합의≥2를 추가 요구. 40 미만 결과 또는 저심박 합의 부족은 filter lock 안 함. 호흡/느린 드리프트가 저심박으로 lock되는 것을 방지 |
| 광대역 HP | 기본 **0.7Hz 유지**, 공통 상수화. Butterworth는 이 주파수 아래를 즉시 0으로 만드는 하드 컷이 아님. 40Hz가 아니라 40 BPM=0.667Hz임 |
| 적응형 HP | 바닥 0.65→0.5Hz. 약 40~62 BPM의 추적 대역에서 기본파를 덜 억제. 수동 HP/LP·기존 Hold·3 BPM 갱신 스로틀링 유지 |
| FFT/자기상관 | 40 BPM 경계 보간을 위한 38 BPM 탐색 여유. 38이 지원/정상 하한이라는 뜻 아님 |
| 초기 시간영역 합의 | 기존 `>42` 조건을 탐색 여유까지 확대, 추정기 간 합의 조건 그대로 유지 |
| 저장 | 품질≥50의 40~200 BPM 학습 허용(기존 42~200). 저장 키·포맷·기존 자료·기본 prior 72·기본 HP 0.7 유지. 195 tracking과 200 저장 상한은 기존 차이를 유지 |
| 잠정 표시 | 기존 품질≥50·합의≥2·prior/fallback/hold 제외·신호 경고 없음에 지원 하한 BPM≥40을 명시. 범위 밖 값을 40으로 강제 보정하지 않음 |
| 유지 | 서맥<60·빈맥>100, CV .14, IBI 정제/불응기, 수동 필터, 3초 제외·유효 5초·8초 시작·2초 갱신, 최종 15/30/60초 판정 정책 |

기본 광대역 HP를 0.6/0.65Hz로 낮춘 후보도 비교했으나, 강한 잡음 44 BPM/12초/seed3에서 기존 44가 86으로 바뀌는 새로운 오차 사례가 생겨 채택하지 않았다. 적응형 HP 바닥 0.6Hz 후보도 0.5Hz보다 결과가 나빴다. 기본값/슬라이더/학습 fallback을 무조건 낮추는 대신, 기존 광대역과 수동 UI를 보존하고 탐색·추적 범위를 조정했다.

## 2. 제공 자료의 적합성

- CSV 2개는 408/406행, 약 29.89/29.84초, timestamp 단조 증가·가변 간격·유효 값이다. 재표본화·시작 과도응답·추정기/브라우저/UI 회귀에 적합하다.
- 과거 안정화 포함 파일로 보고, 첫 샘플 기준 3초 제외 replay를 별도 실행했다(실제 시작 시각이 없어 근사). 새 export에 중복 적용하지 않는다.
- 기존→현재 전체 replay: **78→78 / 77→77 BPM**. 첫 3초 제외: **76→76 / 77→77 BPM**, CV **.0390/.0342**, quality 100·합의 3·irregular false 유지.
- **이 결과를 정상/이상의 정답 라벨로 사용하지 않는다.** 제공 PNG 5장은 과거 앱 출력이며 2 CSV와 확실하게 연결되지 않았다. 외부 기준 기기/ECG/수기 IBI 라벨도 없다. 정상과 비정상 사례가 포함됐다는 사용자 설명과 별개로, 어떤 파일이 어떤 리듬인지 임의로 지정하지 않았다.
- 따라서 이 자료만으로 40 BPM 또는 부정맥 민감도/특이도를 검증할 수 없다. 상세·SHA·재사용 지침·추가 자료 요청은 fixture README 참조.

## 3. 결정적 검증 결과

`tests/low-bpm.test.js`는 다음 784 조합을 매번 실행한다.

- BPM: 38/39/40/41/42/44/45/50/55/60/72/90/100/130
- 길이: 2/5/7/10/12/27/57초(실제 측정의 3초 제외 후 15/30/60초는 약 12/27/57초)
- seed: 1/2/3/42, noiseAmp: .2/1.5
- 40 이상·12초 이상: 약한 잡음 144개 전부 오차≤3 BPM. 강한 잡음은 기존 12/144개 오차>6에서 현재 **8/144개**로 감소. 새로 오차 범위를 벗어난 장기 사례 없음.
- **784개 모두 정확하다는 뜻 아님**: 2~10초 구간은 조기 포착 진단/유한값 확인이며 일률적 정확도 보장 아님. 38/39는 지원 밖 경계 탐색 회귀다.
- 남은 강한 잡음 8개는 모두 기존 잠정 표시 게이트에서 거부됨. **최종 결과에는 그 게이트를 새로 적용하지 않았으므로, 최종 판정에 부정확한 값이 남을 수 있다.** 이 한계를 숨기려고 필터/품질 문턱이나 CV 기준을 완화하지 않았다.

추가 회귀:
- 40 BPM 순수 주기 자기상관·초기 중첩파 중재.
- prior 55/72/130, 기존 HP 0.7 상태에서 5초부터 2초씩 누적 갱신(3 seeds, 기존 locked false/true 모두). 표시 허용 결과 오차≤3, 마지막 27초 tracking 회복.
- .2/.3/.5/.6Hz 느린 파형만 넣은 경우 low-range tracking/lock·잠정 표시 차단.
- 기존 저장 항목 보존·40 학습·39와 저품질 저장 거부.
- 원본 실측 SHA/형식·전체/안정화 제외 결과 회귀 2개.
- 브라우저 실측 replay→이력→상세 파형 2개, 합성 40 BPM 브라우저 추적 1개 추가. 카메라 광학 수집을 모사한 테스트는 아님.

- 40/41/42/44/45 BPM × 12/27/57초 × 시작 offset 0/.35/.8/1.2초 × 3 seed = 180개 오차≤3. 별도 40 BPM 희소 spike 3개 입력도 3 seed 회귀 통과.

기기/움직임/부정맥 분포 전체를 포함한 검증은 아니다. **강한 잡음 정확도, 실제 저심박, 임상 리듬 라벨은 미검증/잔여 한계**로 유지한다.

## 4. 실행 및 성능

- `npm run lint`, `npm run test:i18n`(127키), `npm run test:unit` **41/41**, `npm run build` 통과.
- Playwright 신규 3개 포함 총 23개: PR의 GitHub Actions에서 확인(실행 상태는 해당 SHA의 Checks 참조). 로컬 Chromium의 기존 시스템 라이브러리 부재를 실기기 결함으로 해석하지 않는다.
- 동일 Node v22.22.3에서 미리 생성한 288개 장기 신호를 전·후 코드로 분석: 3회 예열 후 순서를 번갈아 9회, 배치 중앙값 **50.49→51.53ms(+2.05%)**. 단일 분석 평균 약 .18ms. 서버 마이크로벤치마크이며 실제 휴대폰 프레임·배터리 성능 보장은 아님.
- 사용자 완료 보고가 있는 기존 E2E·실기기·운영 확인을 미완료로 되돌리지 않는다. 이번 저심박 변경의 CI 회귀와 실측 정확도 검증은 별도 범위다.

## 5. 후속 자료와 승인 범위

자연스럽게 40~50 BPM이 관측된 30/60초 CSV와 동시 기준 기기 기록(BPM/가능하면 IBI), 파일별 측정 조건·기기·안정화 제외 여부, CSV↔PNG 대응표가 필요하다. 정상/이상 리듬 비교에는 임상적으로 확인된 주석이 별도로 필요하다. 심박을 낮추기 위한 약물·무리한 운동·호흡 조작을 요청하지 않는다.

PR/미리보기까지만 진행하며 병합·운영 이관은 하지 않는다. 28의 대기 파형 격자, 31의 크기, 32 활성 CSS, 34 잠금파일 보류는 유지한다.

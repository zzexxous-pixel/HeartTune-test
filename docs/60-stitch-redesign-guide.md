# 60 · Google Stitch 전체 UX·디자인 재설계 가이드

> 최종 갱신: 2026-10-21 (KST, 2차 개정)
> 목적: Google Stitch로 앱 전체의 UX와 디자인을 자유롭게 재설계하고, 그 결과를 이 저장소(Vanilla JS + ES Modules)에 안전하게 합치는 절차
> 관련: `agent.md` (제품 원칙) · `10-spec.md` (현재 기능 명세) · `50-ad-strategy.md` (광고 정책)

---

## 0. 이 문서의 원칙 (개정 배경)

1차 개정본은 px 단위, 화면 높이 비율, 모든 id 유지까지 요구해서 Stitch가 개선할 여지가 거의 없었다. 이번 개정에서는 다음을 기준으로 바꿨다.

- **Stitch는 디자인과 UX를 자유롭게 바꿔도 된다.** 레이아웃, 색, 글자, 아이콘, 화면 구조, 화면 전환, 문구 배치, 새 화면 제안까지 모두 열려 있다.
- **고정은 "제품 원칙"만 한다.** 사용자의 신뢰와 안전에 관한 것(의료 고지, 진단 표현 금지, 개인정보 원칙 등)과 기능 동작(측정, 저장, 공유)만 고정한다.
- **고정 항목 중 "기준안"은 바꿀 수 있다.** 예: 링 → 파형 → 메시지 순서, 54px 카메라 원. 이런 항목은 Stitch가 바꿔 제안할 수 있지만, 채택은 사용자 승인 후에 한다.
- **id와 class는 강제하지 않는다.** 합치는 과정에서 에이전트가 새 마크업을 기존 기능에 연결한다. Stitch에게 id를 지키라고 요구하지 않는다.

## 1. 제품 원칙 (고정 — 바꾸려면 사용자 승인 필요)

Stitch 프롬프트에 그대로 넣는다. 이 항목을 어기는 디자인은 채택하지 않는다.

1. **의료기기가 아니며 참고용**이라는 표시를 결과와 상세 화면에 항상 둔다. 법적 고지 문구는 지우거나 가리지 않는다.
2. **"진단"이라는 말을 쓰지 않는다.** 결과는 "정상 범위", "리듬이 고르지 않아요"처럼 관찰 표현으로 쓴다.
3. **광고는 측정이력 화면 하단에만 둔다.** 메인 화면, 측정 중, 결과 영역, 공유 이미지에는 광고 자리를 두지 않는다. 광고처럼 보이는 추천 카드도 두지 않는다.
4. **측정 데이터는 기기 밖으로 나가지 않는다.** 서버 전송이나 외부 분석을 전제로 한 UI를 만들지 않는다.
5. **중장년 사용자를 기준으로 한다.** 본문 글자 18px 이상, 핵심 숫자는 가장 크게, 터치 영역 48px 이상, 색만으로 상태를 전달하지 않는다(색 + 아이콘 + 글).
6. **키보드·스크린리더 접근성.** 포커스 표시가 보여야 하고, 아이콘만 있는 버튼에는 읽을 이름이 있어야 한다.
7. **시트(바텀 화면) 패턴 유지 여부는 Stitch가 제안할 수 있다.** 다만 측정이력의 "목록 ↔ 자세히 보기"는 같은 화면 안에서 전환되어야 한다.

## 2. 현재 기준안 (바꿀 수 있음 — 제안 가능, 채택은 승인 후)

현재 앱의 구조이며, Stitch가 더 나은 안을 내면 그 안을 우선 검토한다.

| 영역 | 현재 기준안 | 개선 여지 |
|---|---|---|
| 첫 화면 구조 | 헤더 → 원형 링(카메라 미리보기 포함) → 파형 → 메시지 → 하단 버튼 | 순서, 비율, 정보 묶음 자유 |
| 카메라 미리보기 | 원 54px (사용자 지정) | 크기·위치 변경 제안 가능 (승인 필요) |
| 헤더 | ≡ 메뉴 · 로고 · EN · 설정 | 아이콘과 배치 자유 |
| 결과 색 | 정상 초록, 서맥·빈맥·부정맥 빨강 계열 | 팔레트 전체 재설계 가능 (의미 전달은 유지) |
| 측정이력 | 그래프 + 목록 + 하단 광고 자리 | 그래프 표현, 목록 행 모양 자유 |
| 자세히 보기 | 측정일시·측정시간·맥박·파형·지표 4개·참고 고지 | 정보 묶음과 순서 자유 (공유 이미지도 같은 내용) |
| 시트 | 아래에서 올라오는 바텀 시트 | 전체 화면 패널, 페이지 전환 등 대안 가능 |

| 자료 | 위치 | 용도 |

| 와이어프레임 | `docs/assets/one-screen-wireframe.jpg` | 기존 구조 참고 |

| 문구 목록 | `src/i18n.js` (ko/en) | 문구 길이 확인 |

## 4. Stitch 프롬프트 (목표 중심)

### 4-1. 디자인 방향 (먼저 실행)
> 한국어 중장년 사용자를 위한 건강 측정 웹앱 "오늘심박(HeartTune)"의 디자인 방향을 제안해 줘.
>
> 제품: 스마트폰 후면 카메라와 플래시로 손가락 맥박을 재고 심박수(BPM)를 보여주는 PWA. 결과는 참고용 정보이며 의료기기가 아니다.
> 사용자: 50~70대와 그 자녀. 큰 글씨, 높은 대비, 쉬운 말.
> 분위기: 차분하고 믿을 수 있는 느낌. 과한 의료 느낌이나 장식은 피하되, 지루하지 않게.
>
> 아래 원칙은 반드시 지켜라. (1) "진단" 같은 단정 표현을 쓰지 않는다. (2) 참고용 고지를 지우지 않는다. (3) 광고처럼 보이는 요소를 결과 근처에 두지 않는다. (4) 본문 글자 18px 이상, 터치 영역 48px 이상. (5) 색만으로 상태를 말하지 않는다.
>
> 그 밖의 모든 것(색, 글꼴, 레이아웃, 아이콘, 화면 구조, 전환 효과)은 자유롭게 제안해라. 기존 앱과 달라도 된다. 왜 그렇게 바꿨는지 짧게 설명해 줘.
>
> 출력: 색·간격·글자 크기·모서리 같은 디자인 토큰을 CSS 변수 목록으로 정리.

### 4-2. 첫 화면 (메인)
> 위 디자인 방향으로 메인 측정 화면을 만들어 줘. 320×568 기준 한 화면에 스크롤 없이 들어가야 한다.
>
> 화면에 있어야 하는 것: 측정 시작 버튼, 실시간 심박수 숫자, 측정 진행 상태(시간 또는 진행률), 카메라 미리보기, 파형, 결과 요약과 "자세히 보기" 진입, 결과 공유 진입, 메뉴·언어·설정 진입.
> 배치와 크기는 자유다. 기존 순서(링 → 파형 → 메시지)는 기준안일 뿐이니, 더 나은 배치가 있으면 제안해라.
> 상태별로 만들어라: 대기, 측정 중, 결과 정상, 결과 서맥, 결과 빈맥, 결과 부정맥 참고.
>
> 출력: HTML/CSS. 외부 CDN과 외부 폰트 파일은 쓰지 마라. 이미지 대신 SVG나 CSS로 표현.

### 4-3. 측정이력 (목록과 자세히 보기)
> 같은 디자인 방향으로 "측정이력" 화면을 만들어 줘. 하나의 패널 안에서 두 화면이 전환된다.
>
> 화면 1 (목록): 최근 측정 추세를 보여주는 그래프(세로축 심박수 회/분, 가로축 날짜), 측정 기록 목록(상태, 일시, 측정 시간, 맥박), 기록을 밀어서 삭제하는 동작을 표현. 하단에는 광고가 들어갈 자리와 법적 고지 문구를 둔다. 광고 자리는 고정 높이로 예약하되 광고처럼 보이지 않게.
> 화면 2 (자세히 보기): 목록에서 한 기록을 고르면 왼쪽으로 밀리며 들어온다. 헤더에 뒤로가기, 제목, 공유, 삭제, 닫기. 내용은 측정일시·측정시간·맥박·파형·지표(부정맥, 서맥, 빈맥, 신호 품질)·참고 고지.
>
> 빈 상태, 삭제 대기 메시지("삭제를 취소하시겠습니까?" + 실행 취소 버튼, 광고 바로 위에 뜨는 메시지)도 함께 디자인해라.
>
> 출력: HTML/CSS. 화면 1과 화면 2를 한 파일에 같이 만들어도 되고, 나눠도 된다.

### 4-4. 나머지 화면 (설정, 메뉴, 측정 안내, 법적 고지)
> 같은 디자인 방향으로 설정, 메뉴, 측정 안내, 법적 고지(개인정보 처리방침 포함) 화면을 만들어 줘. 화면 구조를 통일해도 좋고, 더 나은 방식이 있으면 바꿔도 된다. 법적 고지 문구는 모두 포함해라.

### 4-5. 피드백 프롬프트 (결과를 받은 뒤)
> 방금 만든 화면에서 (구체적 문제)를 바꿔 줘. 나머지 화면과 원칙은 그대로 둬라. 바꾼 부분만 설명해 줘.

한 번에 한 가지씩 바꾸는 것이 결과가 안정적이다.

## 5. Stitch 결과를 저장소에 합치는 절차

Stitch 결과는 "디자인 시안"이다. 기능은 기존 코드가 담당한다. 에이전트가 다음을 한다.

1. **내보내기 형식:** HTML/CSS만 받는다. Tailwind와 React는 이 저장소 구조와 맞지 않으므로 받지 않는다.
2. **기능 연결:** 새 마크업에 기존 기능을 다시 연결한다. 기능 연결 지점은 에이전트가 찾아서 매핑한다. Stitch에게 id를 지키라고 요구하지 않는다.
   - 측정 시작·중지, 결과 표시, 이력 저장·삭제, 공유 이미지 생성, 시트 열기·닫기, 언어 전환은 기존 `src/main.js`, `src/features/*.js`가 담당한다.
3. **문구:** 모든 문구는 `src/i18n.js`의 키로 바꾼다. ko와 en 키 개수가 같아야 한다(`npm run test:i18n`).
4. **경로와 자산:** 모든 참조를 `./` 상대경로로 정리한다. 외부 CDN과 절대경로는 제거한다. 새 파일은 `sw.js`의 ASSETS와 `scripts/build-dist.js`의 RUNTIME_FILES에 등록한다.
5. **제품 원칙 점검:** 1절 원칙을 모두 만족하는지 확인한다. 광고 위치, 참고 고지, 진단 표현, 데이터 전송 여부를 본다.
6. **검증:** `npm run lint`, `npm run test:i18n`, `npm run test:unit`, `npm run test:e2e`, `npm run build`. 320×568과 393×851에서 가로 넘침과 글 잘림을 확인한다. 측정 흐름(시작 → 측정 → 결과 → 자세히 보기 → 공유 → 이력 → 삭제 취소)을 직접 한 번 따라간다.
7. **문서 갱신:** 바뀐 화면 구조는 `10-spec.md`, 원칙이 바뀌었으면 `agent.md`에 기록한다.

## 6. 피해야 할 것 (원칙 위반)

- 결과 근처나 측정 중에 광고처럼 보이는 카드나 배너를 두는 것
- "진단", "치료", "이상 없음 보장" 같은 단정 표현
- 참고 고지를 접힘 메뉴 안으로 숨기는 것
- 색만으로 정상과 이상을 구분하는 것
- 아이콘만 있고 이름이 없는 버튼 (스크린리더가 읽을 수 없음)
- 긴 영어 문구가 320px에서 잘리는 것 (en 전환 확인 필수)

이 밖의 디자인 선택은 자유다. 기존과 달라도 되고, 더 나은 구조를 제안해도 된다.

| 측정 중단 버튼의 흰 배경+붉은 글자 | 시작(크림슨 채움)과 구분되도록 측정 중 상태에 적용 |
| 자세히 보기의 큰 BPM 히어로, 지표 행 목록(아이콘+상태 필) | BPM 카드를 맨 위 큰 숫자로, 지표는 1열 행 목록으로 변경 (기존 2열 그리드는 320px에서 좁았음) |
| 이력 그래프의 정상 범위(60~100) 밴드, 최저/평균/최고 요약, "N회 저장됨" | 표시 기준은 바꾸지 않고 기록에서 계산되는 사실 정보만 추가 |
| 공유 카드의 크림슨 BPM·다크 파형 | PNG 레이아웃·치수는 유지하고 색만 교체 |
